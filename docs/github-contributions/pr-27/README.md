## 이번에 한 일

텔레그램 채널의 리포트 PDF를 수집하고 요약해 저장하는 배치를 추가했습니다. **#18에서 정리한 테이블·분류·Alembic 구조를 그대로 사용합니다.** #18 병합 후 이 PR을 병합합니다.

- PDF에서 본문과 발행처·종목·투자의견·목표주가를 추출합니다.
- **네이버에 이미 있는 PDF는 해시로 비교해 텔레그램 저장·요약을 건너뜁니다.** 파일명이 달라도 같은 파일이면 제외합니다.
- OpenRouter를 통해 DeepSeek으로 요약하고, Python으로 길이·숫자·목표주가 등을 검증합니다. 실패하면 최대 3회 시도하며 통과한 결과만 저장합니다.
- 재수집이나 요약 재생성으로 기존 정상 데이터를 덮어쓰지 않도록 보호합니다.
- 계정별 로그인·채널 접근 확인 명령을 추가했습니다. 접근·수집 실패는 오류로 종료합니다.
- 본문을 확보하지 못한 자료는 요약하지 않습니다. **OCR은 제외했습니다.**

실행 방법은 `ai/README.md`에 정리했습니다.

```bash
cd ai
uv sync
uv run alembic upgrade head
# 최초 로그인·채널 접근 확인은 README 참고
# 네이버 수집 후 텔레그램 수집
uv run python -m app.collectors.telegram --days 7 --channel sunstudy1234
uv run python -m app.collectors.summary --dry-run
uv run python -m app.collectors.summary --report summary-result.json
```

- 데이터: 네이버 474건, 텔레그램 248건. 텔레그램 206건 요약, 본문 부족 등 42건 제외.
- 검증: 테스트 199개, Ruff, lockfile·diff 검사, `alembic check` 통과.

## 리뷰에서 봐주셨으면 하는 곳

- PDF 수집부터 요약·저장까지 정상적으로 실행되는지, 네이버와 중복된 PDF가 제외되는지 봐주세요.
- 요약이 원문 내용을 잘 전달하는지, 검증 실패 시 잘못된 결과가 저장되지 않는지 확인 부탁드립니다. 프롬프트는 `ai/app/llm/prompts/analyst_summary.md`에 있습니다.

## 고민했던 점 · 다른 선택지

네이버처럼 같은 테이블에 저장하되, 네이버에 없는 PDF만 텔레그램에서 추가하도록 했습니다. 네이버는 제공 요약을 사용하고 텔레그램은 본문에서 생성합니다. 텔레그램 채널끼리 같은 PDF를 공유한 경우에는 정상 요약을 재사용합니다.

모델 응답을 그대로 저장하지 않고 코드로 검증합니다. 다만 숫자가 원문에 있어도 항목·기간을 잘못 연결한 오류까지 잡지는 못하며, 발행처·분류는 파일명과 본문을 바탕으로 추출합니다.

날짜는 네이버의 업로드일과 텔레그램 파일명 날짜를 그대로 사용합니다. 익일이나 주말 이후
게시되어 실제 발간일과 차이가 날 수 있습니다. 표지 날짜를 확인하는 것이 정확하지만,
본문에서 자동 추출하면 다른 날짜와 혼동할 수 있어 현재는 유지했습니다. 하루 이틀 차이가
서비스 판단에 중요한 영향을 주게 되면 발간일 추출을 다시 검토하려 합니다.
